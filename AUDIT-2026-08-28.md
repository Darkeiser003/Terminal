# Auditoría observable del banner y la rejilla

## Alcance

- Código revisado: `src-tauri/src/terminal/tabs.rs`, `src-tauri/src/platform/system_info.rs`, `src/components/TerminalPane.svelte` y `tests/e2e/smoke.mjs`.
- Sesión nativa observada con `src-tauri/target/debug/winslim-terminal.exe`.
- Log correlacionado: `%APPDATA%/winslim-terminal/logs/main.log`.

## Evidencia reproducida

1. En la sesión `c4hn7v` el log no registró errores, pero al pasar a dos paneles una casilla conservaba el banner completo y otra el compacto. La captura `winslim-audit-native-split.png` conserva ese estado.
2. En sesiones anteriores aparecía `ReferenceError: paneCountChanged is not defined` en `TerminalPane.svelte`; se corrigió y se añadió una comprobación de alcance al test frontend.
3. El arranque generaba el archivo de banner con el viewport persistido (por ejemplo, 48 columnas) antes de que el xterm midiera 99 columnas. Al refluirlo encima del prompt aparecían valores concatenados y separadores residuales.
4. El PTY y el repintado de resize emitían `pty-data` desde hilos distintos. Sin serialización, dos bloques podían llegar a xterm intercalados.

## Correcciones aplicadas

- `TabManager` serializa las emisiones de salida y el vaciado de la cola inicial.
- Las pestañas nuevas retienen el inicializador hasta el primer `pty_resize` real; justo antes se regeneran el archivo y el layout para ese tamaño.
- Un repintado pendiente que coincide con el viewport recién impreso se descarta al recibir el marcador de inicialización; así no se superpone una segunda cabecera.
- El smoke exige cabecera propia, modo homogéneo, ausencia de líneas mezcladas y ausencia de prompt antes del último campo del banner.

## Segunda pasada: transición real de rejilla y builds cruzadas

La interacción nativa 1 → 2 → 3 → 4 reprodujo un caso que la batería anterior
no cubría: la primera casilla podía conservar el viewport anterior mientras las
casillas nuevas ya mostraban el banner compacto. El log correlacionado registró
`resize` para las cuatro pestañas, pero el primer repintado no siempre se
reintentaba cuando la shell estaba ocupada. `TerminalPane.svelte` ahora marca
el cambio de rejilla antes del resize y programa un segundo intento sin cursor;
la captura `C:\Users\Administrador\AppData\Local\Temp\winslim-audit-pass-fixed-split4.png`
muestra las cuatro casillas homogéneas después del arreglo.

La build Linux en Ubuntu WSL terminó correctamente en **547 s** y produjo un
AppImage de **88 MB**. El smoke interno validó runtime, ventana, frontend, IPC,
xterm y PTY; `sha256sum -c` y `linux/validate-release.sh` también pasaron. Se
observaron solo avisos no fatales de linuxdeploy (`AppStream` ausente, `usr/lib64`
inexistente y `find` sin permiso sobre `lost+found`).

La build Linux descubrió además una regresión de flujo: `npm ci` en el checkout
compartido eliminaba el binding opcional `@tauri-apps/cli-win32-x64-msvc`.
`linux/build.sh` ahora aparta temporalmente el `node_modules` Windows, instala el
árbol Linux y lo restaura mediante `trap`, incluso si la build falla. La
verificación de scripts cubre este contrato.

Tras restaurar el binding Windows, `npm run e2e:build` volvió a producir el EXE
debug y la batería completa terminó con **121 comprobaciones de build, 236
contratos de tests, 608 tests Rust, svelte-check sin errores, fmt y Clippy sin
warnings**. En una repetición, Maven Central respondió con timeout de 5 s; el
checker lo trató como aviso externo y continuó, sin afectar a las validaciones
locales.

## Build Windows release y comprobación final

La build real `windows/build.ps1 -NoRun -NoExtendedTests -AllowOfflineChecks
-NonInteractive` terminó correctamente en **245,9 s**. En el entorno con red se
validaron 27 enlaces, 16 fuentes de instalación y 71 identificadores de WinGet;
el frontend produjo 144 módulos y `svelte-check` quedó en 0 errores/0 avisos.
Cargo compiló el ejecutable release x64 y la validación PE/runtime comprobó 37
artefactos. El smoke mínimo confirmó ventana, frontend, xterm, IPC y primera PTY.

La carpeta portable resultante contiene `winslim-terminal.exe`, ConPTY,
`OpenConsole.exe`, `WebView2Loader.dll` y 12 recursos integrados. El ZIP
`WinSlimTerminal-Unpacked-1.4.4.zip` pesa 4,2 MB y su SHA-256 se añadió al
manifiesto sin borrar el hash previo del AppImage Linux; ambos hashes coinciden
con `Get-FileHash` (2/2). Esta ejecución omitió deliberadamente el E2E WebDriver
ampliado (`-NoExtendedTests`), porque este host no tiene `msedgedriver.exe`.
